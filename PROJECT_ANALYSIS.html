Анализ проекта Ishvara и Топ-10 рекомендаций

Комплексный технический аудит: архитектура, безопасность, Mongoose, трекер и Meta CAPI.

1. Архитектура и стек системы

Ishvara объединяет четыре ключевые маркетинговые подсистемы:

  • Поведенческий трекер: клиентский легковесный скрипт tracker.ts для трекинга скролла, кликов, dwell time и перехвата Facebook cookies.
  • Telegram-мультибот: модуль на Telegraf с маршрутизацией через вебхук и ретрансляцией сообщений администратора.
  • Meta Conversions API (CAPI): серверный шлюз передачи событий воронки лидов в Facebook Graph API.
  • CRM-аналитика: SPA-приложение на чистом TypeScript и Web Components с таймлайнами активности гостей.

2. Топ-10 приоритетных рекомендаций

Критический баг

1. Двойное чтение Response (result.json()) в Meta CAPI

server/src/controllers/guests.controller.ts:82-87

При получении ошибки от Meta Graph API код повторно вызывает await result.json() на уже прочитанном потоке. В результате сервер падает с исключением TypeError: Body has already been consumed, скрывая саму причину ошибки от Facebook.

Решение

Использовать уже распарсенный результат первичного чтения json без повторного вызова метода.

Производительность и память

2. Утечка памяти при операциях без курсора (.cursor())

server/src/controllers/statistics.controller.ts:98 & server.controller.ts:48

Методы findUnregistredEvents, setTags и arhive1 вызывают Guest.find().lean() без ограничений. Загрузка десятков тысяч документов с массивами событий вызывает OOM (Out-of-memory) и намертво блокирует Event Loop Node.js.

Решение

Использовать потоковые Mongoose-курсоры: Guest.find({...}).cursor({ batchSize: 500 }) с обработкой батчами.

Индексы базы данных

3. Ошибочный индекс в Mongoose-схеме Guest

server/src/models/Guest.ts:55

В схеме прописано GuestSchema.index({ pid: 1 }). Поля pid в модели нет (используется projectId). Запросы фильтрации по проекту выполняют полное сканирование коллекции (COLLSCAN).

Решение

Заменить индекс на актуальный: GuestSchema.index({ projectId: 1, createdAt: -1 }).

Кроссплатформенность сборки

4. Ошибка в регистре экспорта типов (IGuest.ts vs Guest.ts)

shared/types/index.ts:3

Файл index.ts экспортирует export * from "./Guest", в то время как файл на диске называется IGuest.ts. В Linux-системах (Docker, Cloud Run) сборка падает из-за case-sensitive путей.

Решение

Исправить экспорт на точное имя: export * from "./IGuest.js".

Оптимизация БД

5. Проблема N+1 запросов при фоновой архивации

server/src/controllers/server.controller.ts:108

В цикле архивации на каждого гостя вызывается отдельный await Guest.replaceOne(...). Это создает тысячи синхронных сетевых обращений к MongoDB.

Решение

Накапливать операции пакетами и выполнять через Guest.bulkWrite([...]).

Безопасность

6. Неэффективный rateLimit эндпоинта создания сессий

server/src/controllers/tracker.controller.ts:8-14

Параметр max: 10000 фактически не защищает сервер от ботов, генерирующих миллионы мусорных сессий гостей.

Решение

Снизить порог до разумных пределов (60–100 запросов/час) и включить доверенный прокси app.set("trust proxy", 1).

Конфигурация

7. Захардкоженный прод-URL в клиенте трекера

client/src/tracker.ts:1-4

URL Cloud Run прописан статичной строкой, требуя ручного комментирования при локальном тестировании.

Решение

Использовать import.meta.env.VITE_API_URL с переключением через режимы сборки Vite.

CI/CD и развертывание

8. Абсолютные Windows-пути в скрипте деплоя

deploy_project.ts:5-6

Константы A:/pProd/ishvara жестко привязаны к локальной файловой структуре.

Решение

Использовать переменные окружения и метод path.resolve(...).

Надежность API

9. Отсутствие валидации схем запросов через Zod

server/src/controllers/tracker.controller.ts

Данные req.body в роутах трекера не валидируются. Некорректный формат событий может нарушить структуру документов базы.

Решение

Описать Zod-схемы для валидации тела запросов /start, /push-events, /save-cookies.

Гигиена кода

10. Очистка репозитория от мусорных файлов и дубликатов

server/src/controllers/tgbot_admin.controller copy.ts

Файлы-копии и системные файлы desktop.ini засоряют поиск и тратят токены контекста.

Решение

Удалить файлы-дубликаты и добавить исключения в .gitignore.
