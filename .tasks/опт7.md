# Оптимизация 7: 2-байтовая побитовая упаковка событий и почасовой процессор

## 1. Контекст и проблема
- В коллекции `guests` (93 732 записи) поле `events` занимает **23.8 MB (71.6% базы)** из-за оверхеда вложенных массивов BSON.
- 56% всех событий — это микро-шаги скролла `"D"` и `"U"` каждые 300px.
- Внутри страниц используется ровно **38 уникальных кодов событий**.
- 99.2% всех дельт между событиями $\le 102$ секунды (медиана 0.5с).

---

## 2. Спецификация 2-байтового (16-битного) протокола

Каждое внутристраничное событие пакуется ровно в **2 байта (16 бит)**:
```
[ Биты 15..10: Код события (6 бит, 0..63) ] [ Биты 9..0: Дельта времени Δt (10 бит, 0..1023) ]
```

### 2.1. Словарь кодов (6 бит, 0..63)
- `0`: Маркер смены страницы (`["t...", pageId]`).
- `1..37`: Известные коды внутри страниц:
  - 1: `"D"`, 2: `"U"`, 3: `2`, 4: `9`, 5: `"c"`, 6: `3`, 7: `4`, 8: `1`, 9: `5`, 10: `11`, 11: `6`,
  - 12: `"inner-routing"`, 13: `"tours-show"`, 14: `"open-tour-details"`, 15: `"small-search-tours"`,
  - 16: `"tour-filter"`, 17: `"show-booking-form"`, 18: `7`, 19: `"adv-tour-click"`, 20: `"c-tBaner"`,
  - 21: `"tour-go-to-firm"`, 22: `"tours-search"`, 23: `"copy-firm-phone"`, 24: `10`, 25: `"copy-firm-email"`,
  - 26: `"tour-filter-mobile"`, 27: `"show-tour-firm-contacts"`, 28: `"copy-booking-phone"`,
  - 29: `"tours-ordering"`, 30: `"tour-set-like"`, 31: `"v:start"`, 32: `"v:half"`, 33: `"v:complete"`,
  - 34: `"btnMaps"`, 35: `12`, 36: `"/meditation"`, 37: `"goalBtnClick"`
- `38..61`: Резерв под будущие коды.
- `62`: Неизвестный код (fallback).
- `63`: Маркер длинной паузы $> 102.3$ сек.

### 2.2. Дельта времени (10 бит, 0..1023)
- Шаг 0.1 сек (от 0.0 до 102.3 сек): `deltaTenths = Math.round((currentTime - lastTime) * 10)`.
- Если $\Delta t > 102.3$ сек: пишется маркер паузы `(63 << 10) | 1023` (пока остаток не станет $\le 1023$).

### 2.3. Заголовок страницы (при коде 0)
- Маркер: `0x0000` (2 байта).
- Timestamp: 6 байт (`Date.now()`, 48-бит unsigned BE).
- PageId: 2 байта (`uint16 BE`, 0..65535).
- Итого заголовок: 10 байт (встречается 1–3 раза за визит).

## 3. Подробный нумерованный план реализации

### Шаг 1. Создание кодека событий в `shared`
- **Файл:** `shared/utils/eventCodec.ts`
- **Функции:**
  - `encode2ByteEvents(events: Array<[number | string, number | string]>): Uint8Array`
  - `decode2ByteEvents(buf: Uint8Array | Buffer): Array<[number | string, number | string]>`
  - `normalizeEvents(rawEvents: any): Array<[number | string, number | string]>` (поддержка `Array`, `Buffer`, `{ type: 'Buffer', data: [...] }`, `String`, `null`).
- **Экспорт:** обновить `shared/types/IGuest.ts` (`events?: [number | string, number | string][] | Uint8Array | Buffer | any`).

### Шаг 2. Оптимизация трекера скролла
- **Файл:** `client/src/tracker.ts`
- **Изменения:**
  - Флаг `hasFirstScroll = false` и переменная `lastScrollY = 0`.
  - При `!hasFirstScroll && window.scrollY >= 5`: немедленная фиксация `track("D")`, `hasFirstScroll = true`, `lastScrollY = window.scrollY`.
  - Для последующих скроллов: шаг `yShag = 600px` относительно `lastScrollY`:
    ```ts
    if (Math.abs(currentY - lastScrollY) >= yShag) {
      this.track(currentY > lastScrollY ? "D" : "U");
      lastScrollY = currentY;
    }
    ```
  - Запустить сборку трекера: `npm run build:tracker`.

### Шаг 3. Обратная совместимость в CRM
- **Файл:** `client/src/components/c-guests/c-guest-block/c-guest-block.ts`
- **Изменения:**
  - Импортировать `normalizeEvents` из `@shared/utils/eventCodec`.
  - В цикле отрисовки таймлайна (строка ~388):
    ```ts
    const events = normalizeEvents(this.data.events);
    for (let i = 0; i < (events.length ?? 0); i++) {
      const event = events[i];
      ...
    }
    ```
  - CRM одинаково прозрачно читает как старые записи-массивы, так и новые бинарные буферы.

### Шаг 4. Обновление модели Mongoose и сокращение имен полей
- **Файл:** `server/src/models/Guest.ts`
- **Изменения:**
  - `events: { type: Schema.Types.Mixed, default: undefined }` (позволяет сохранять как `Array`, так и BSON `BinData` / `Buffer`).
  - Сокращение ключевых полей с помощью Mongoose `alias`:
    - `ca: { type: Date, default: Date.now, alias: "createdAt" }`
    - `lc: { type: Date, alias: "lastChange" }`
    - `pid: { type: Number, alias: "projectId" }`
  - Включение опций схемы: `{ versionKey: false, toJSON: { aliases: true, virtuals: true }, toObject: { aliases: true, virtuals: true } }` (удаляет `__v` и сохраняет для фронтенда полные имена полей).
  - В контроллерах агрегаций ([guests.controller.ts](file:///a:/ishvara/server/src/controllers/guests.controller.ts)): использовать `$ifNull: ["$lc", "$lastChange"]` и `$ifNull: ["$ca", "$createdAt"]` для 100% совместимости с немигрированными и мигрированными записями.

### Шаг 5. Почасовой процессор (Теги + Статистика + Сжатие)
- **Файл:** `server/src/services/hourlyProcessor.service.ts`
- **Логика:**
  1. Выборка через `.cursor({ batchSize: 500 })` гостей с `b: { $exists: false }` и `lastChange < Date.now() - 30 * 60 * 1000`, у которых `events` является массивом.
  2. Извлечение страниц через `PagesStatistics` $\to$ запись в `guest.pages`.
  3. Расчет тегов (`TAGS.scroll.was`, `TAGS.page.tours`, `TAGS.goals.middle`, `TAGS.goals.top` и т.д.) $\to$ запись в `guest.tags`.
  4. Проверка на пустого гостя (нет тегов, `level == 0`, нет контактов) $\to$ архивация в `b: true` с обязательным удалением поля `createdAt` (дата создания берется из `_id`). У активных гостей поле `createdAt` не трогаем, чтобы не ломать графики и аналитику.
  5. Для гостей с действиями: упаковка `events` в 2-байтовый Buffer через `encode2ByteEvents(guest.events)`.
  6. Применение изменений через `Guest.bulkWrite()` пачками по 500 документов.
  7. Экспорт функции `initHourlyProcessorCron()`, запускающей цикл раз в 1 час (`setInterval` на 3 600 000 мс).

### Шаг 6. Регистрация сервиса в `server/src/index.ts`
- Подключить `initHourlyProcessorCron()` при старте сервера в `app.listen`.

### Шаг 7. Скрипт миграции исторических данных
- **Файл:** `server/src/scripts/migrate_pack_events.ts`
- **Задача:** 
  1. Переименование полей в базе через `Guest.updateMany({}, { $rename: { lastChange: "lc", createdAt: "ca", projectId: "pid" }, $unset: { __v: "" } })` — экономия **~2.18 MB**.
  2. Проход по всем записям с `events` в виде массива и упаковка их в 2-байтовый Buffer — экономия **~20+ MB**.
  3. Вычистить поле `ca` (`createdAt`) у пустых ботов (`b: true`) — экономия еще **~1.4 MB**.
  4. Удалить пустых ботов старше 14 дней.

## 4. Ожидаемый эффект
- Сокращение размера `events` с **~24 MB до ~3.4 MB (в 7–10 раз)**.
- Дополнительная экономия на сокращении имен полей (`lc`, `ca`, `pid`, удаление `__v`): **~2.18 MB**.
- Сокращение количества новых скролл-событий трекера на **50–70%**.
- Гарантированная детекция первого скролла человека от 5px.
- Полная 100% обратная совместимость со всеми существующими записями в CRM благодаря алиасам Mongoose.
